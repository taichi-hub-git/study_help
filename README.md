# テスト対策アプリ

講義PDFをアップロードし、PDFごとに「PDF / 要約 / クイズ / フラッシュカード / マインドマップ / 暗記」の6タブで学習できる、ローカル完結のテスト対策アプリです。PDFはフォルダに分類でき、フォルダ単位で複数PDFを横断した「クイズ（問題数指定可）/ 暗記 / テスト直前」も作成できます。AI生成には Gemini API を使用します（自分のAPIキーが必要です）。PDFファイル・抽出テキスト・AI生成物はすべてローカル（`data/`）に保存されます。

## セットアップ

1. 依存パッケージをインストール

   ```bash
   npm i
   ```

2. Gemini APIキーを設定

   `.env.local` を開き、`GEMINI_API_KEY` に自分のAPIキーを設定してください。

   ```
   GEMINI_API_KEY=AIza...
   ```

   APIキーは [Google AI Studio](https://aistudio.google.com/apikey) から発行できます。

3. 開発サーバーを起動

   ```bash
   npm run dev
   ```

   [http://localhost:3000](http://localhost:3000) を開いてください。

## 使い方

1. トップページでPDFをドラッグ&ドロップ（またはクリックして選択、複数ファイル可）してアップロードします。ページ単位でテキストが抽出され、ローカルのSQLiteに保存されます。抽出時にPDFを実際にレンダリングし、赤字など色付きで強調されていたテキストも検出して保存します（後述の「テスト直前」で使用）。アップロード時に**要約も自動生成**されます（フォルダ機能がこれを再利用するため）。
2. アップロード済みPDFをクリックすると閲覧画面に移動します。上部のタブでPDF/要約/クイズ/フラッシュカード/マインドマップ/暗記を切り替えられます。PDFタブは全ページを縦スクロールで閲覧できます。
3. 「2画面」チェックボックスをONにすると左右2ペインになり、各ペインが独立してタブを選べます（例: 左にPDF、右にクイズ）。
4. 要約・クイズ・フラッシュカード・マインドマップ・暗記は初回表示時にAIが生成し、結果はローカルにキャッシュされます。同じ条件であれば再度Gemini APIを呼び出さずキャッシュを返すため、API利用コストを抑えられます。明示的に「再生成」ボタンを押した場合のみ、新しく生成し直します。
5. クイズ・フラッシュカード・暗記の各項目には出典ページが表示され、クリックするとそのペインのPDFタブが該当ページにジャンプします。
6. トップページで「フォルダ」を作成し、PDFをフォルダに移動できます（アップロード時にフォルダへ直接追加することも可能）。フォルダ画面では、フォルダ内の全PDFを横断した「クイズ」（難易度・トピック・問題数を指定可能）、「暗記」、「テスト直前」（試験に出る可能性が高い項目のまとめ）を作成できます。出典は「ファイル名 p.N」で表示され、クリックすると該当PDFの該当ページが別タブで開きます。
7. 「テスト直前」は、元のPDFで赤字などの色付きで強調されていた内容（🔴強調）と、AIが内容から試験に出やすいと判断した内容（🤖推測）を分けて一覧表示します。
8. PDF・フォルダはどちらも削除できます（フォルダを削除すると、中のPDFも完全に削除されます）。画面左下に、これまでのAI呼び出しで使用した合計トークン数が表示されます。

### フォルダ機能はトークン効率のため要約ベースで動きます

フォルダ内の全PDFの生テキストを毎回まとめて送ると、フォルダが大きくなるほどコストが跳ね上がるため、フォルダ機能はすべて**各PDFの要約（と、テスト直前・暗記では赤字などの強調テキスト抜粋）** を入力にしています。

- **テスト直前・暗記**: PDFごとに1回だけ生成してキャッシュし（`generations` テーブル）、フォルダ画面はそれらを集めて表示するだけ（フォルダ単位のAI呼び出しはありません）。新しいPDFを追加した時は、その新しいPDFの分だけ生成されて追加され、既存PDFの結果はそのまま再利用されます。
- **クイズ**: 出題数・トピックの指定を横断的に満たす必要があるため、フォルダ内の各PDFの要約をまとめた1回の呼び出しのままですが、生テキストではなく要約を渡すことでコストを抑えています。
- 要約ベースになったことで、出典ページ（`p.N`）は「わかる場合のみ表示」になります（要約はページ番号を保持していないため）。赤字強調から作られた項目は元のページ番号を維持しますが、要約のみから推測された項目はページ番号なしで表示されることがあります。
- 一部のPDFの生成に失敗しても（レート制限など）、成功した他のPDFの結果は表示され、「再生成」で失敗分だけ再試行できます。

## 技術スタック

- Next.js（App Router, TypeScript strict）/ Tailwind CSS
- SQLite（`better-sqlite3`）: PDFメタデータ・フォルダ・ページテキスト・AI生成物のキャッシュ・トークン使用量
- `pdfjs-dist`（サーバー側でページ単位のテキスト抽出）/ `react-pdf`（クライアント側のPDF表示、workerはCDNを使わず `public/pdf.worker.min.mjs` にローカル配信）
- `@napi-rs/canvas`: サーバー側でPDFページを実際にレンダリングし、テキストの描画色をピクセルサンプリングして「赤字などの強調テキスト」を検出（`lib/pdf.ts`）
- `markmap-lib` + `markmap-view`（マインドマップ描画）
- `zod`（AI出力のバリデーション）
- `@google/genai`（Gemini API SDK。Route Handler経由でのみ呼び出し。APIキーはサーバー側のみで使用）

## モデルの変更

使用するモデル名は [lib/gemini.ts](lib/gemini.ts) の `MODEL` 定数1箇所にまとめてあります。ここを書き換えるだけで、アプリ全体の生成に使うモデルを差し替えられます。

```ts
export const MODEL = "gemini-2.5-flash";
```

## データの保存場所

- アップロードしたPDF本体: `data/pdfs/`
- SQLiteデータベース（メタデータ・ページテキスト・AI生成キャッシュ）: `data/app.db`

`data/` は `.gitignore` 対象なので、リポジトリにはコミットされません。
